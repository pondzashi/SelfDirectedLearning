## 1. ภาพรวมสถาปัตยกรรม

```
Google Sheet (ฐานข้อมูล)  <──อ่าน/เขียน──>  Apps Script Web App (Code.gs + HtmlService)
 Questions / Sessions /                         ├─ ?page=exam&t=<token>   หน้าสอบของลูก
 Answers / Results /                            └─ ?page=dashboard        หน้าผู้ปกครอง
 Settings / Reports
```

- โฮสต์ทั้งหมดบน Google ไม่มีค่าใช้จ่าย ไม่ใช้ Google Forms
- ผู้สอบมีคนเดียว (ไม่รองรับหลายคนใน Phase 1) แต่ทุกตารางมี session_id จึงต่อยอดได้
- **server เป็นผู้ตัดสินเวลาทั้งหมด** client แค่แสดงผล

## 2. โหมดการสอบ

| โหมด | รายละเอียด | เวลา | แสดงเฉลย |
|---|---|---|---|
| **Mock รายวิชา** | เลือก 1 วิชา สุ่มตาม blueprint ของวิชานั้น สอบวันละวิชาได้ | เวลาวิชานั้น (§4) | ตามนโยบายเฉลย (§7.4) |
| **Mock เต็มชุด** | 3 วิชาต่อกันตามลำดับ อังกฤษ → ไทยและสังคม → ความถนัดศิลป์ | แยกรายวิชา | ตามนโยบายเฉลย |
| **Drill อัตโนมัติ** | ดึงทักษะ 🔴🟡 ของวิชาที่เลือก ทักษะอ่อนกว่าได้ข้อมากกว่า ปุ่มปิดถ้าวิชานั้นยังไม่มีผล Mock และแสดงข้อความ "ต้องทำ Mock วิชานี้อย่างน้อย 1 ครั้งก่อน" | ตั้งเอง (ค่าเริ่มต้น 1 นาที/ข้อ) | **ทันทีหลังตอบแต่ละข้อ** |
| **Drill เลือกเอง** | เลือกวิชา ทักษะ (หลายอัน) จำนวนข้อ และเวลา ใช้ได้ตั้งแต่วันแรก | ตั้งเอง | **ทันทีหลังตอบแต่ละข้อ** |

ผล Drill เก็บใน Sessions/Answers/Results เหมือนกัน แต่ติดป้าย `mode=drill_auto|drill_custom` และ **ไม่ถูกนำไปคิดคะแนน "ภาพรวม" ของ Mock** (แสดงแยกในส่วนฝึก) เพื่อไม่ให้ข้อสอบ Drill ที่เน้นทักษะอ่อนดึง % ลงเทียม ส่วน % รายทักษะ ใช้ข้อมูลจาก Mock เท่านั้นเป็นค่าเริ่มต้น มีสวิตช์ใน Settings (`skill_include_drill`) ถ้าอยากรวม

## 3. โครงสร้าง Google Sheet

ทุกแท็บแถวที่ 1 = หัวคอลัมน์ (ชื่อภาษาอังกฤษตัวพิมพ์เล็ก ห้ามเปลี่ยน โค้ดอ้างตามชื่อ ไม่ใช่ตำแหน่ง) เวลาทั้งหมดเก็บเป็น ISO 8601 UTC ใน `*_at` และเป็น epoch ms ใน `*_ms` (ใช้คำนวณ)

### 3.1 แท็บ `Questions` (คลังข้อสอบ — วาง CSV ต่อท้ายได้)

| คอลัมน์ | ชนิด/ค่า | หมายเหตุ |
|---|---|---|
| `id` | ข้อความไม่ซ้ำ เช่น `EN-VOC-001` | รูปแบบ `<วิชา>-<ทักษะ>-<เลข>` |
| `subject` | `english` / `thai_social` / `art` | รหัสวิชา (ชื่อไทยแสดงจาก Settings) |
| `skill` | ดู §5 | ต้องตรงรายการทักษะใน Settings |
| `difficulty` | 1 ง่าย / 2 กลาง / 3 ยาก | |
| `cognitive` | `จำ` / `เข้าใจ` / `ประยุกต์` / `วิเคราะห์` | ระดับการคิด (Bloom แบบย่อ) |
| `group_id` | ว่าง หรือรหัสกลุ่ม | ข้อที่ใช้บทอ่าน/รูปร่วมกัน ระบบสุ่ม**ทั้งกลุ่มไปด้วยกัน** เรียงตามเลขในกลุ่ม |
| `passage` | ข้อความยาว (ว่างได้) | บทอ่านร่วมของกลุ่ม ใส่ที่แถวแรกของกลุ่มพอ (หรือทุกแถวก็ได้) |
| `stem` | โจทย์ | รองรับขึ้นบรรทัดใหม่ และ `**ตัวหนา**` อย่างง่าย |
| `choice_a`…`choice_d` | ตัวเลือก 4 ข้อ | |
| `image_url` | ว่าง / `drive:<fileId>` / URL https | รูปประกอบโจทย์ ถ้าเป็น `drive:` ระบบดึงจากโฟลเดอร์ Drive ของเจ้าของแล้วส่งเป็น data URI จึงไม่ต้องแชร์รูปสาธารณะ |
| `answer` | `A`–`D` | เฉลย (ตามลำดับเดิมใน CSV ก่อนสุ่มตัวเลือก) |
| `explanation` | ข้อความ | ทำไมข้อนี้ถูก |
| `why_a`…`why_d` | ข้อความ | เหตุผลที่ตัวเลือกนั้นผิด (ช่องของข้อที่ถูกเว้นว่างหรือใส่ "ถูก") |
| `takeaway` | ข้อความสั้น | หลักที่ควรจำ |
| `explanation_image_url` | ว่าง/ชนิดเดียวกับ image_url | รูปประกอบคำอธิบาย |
| `fact_date` | `YYYY-MM-DD` (ว่างได้) | ใช้กับข่าวปัจจุบัน/ข้อเท็จจริงที่เปลี่ยนได้ |
| `status` | `active` / `flagged` / `retired` | ระบบสุ่มเฉพาะ `active`; ลูกแจ้งผิด → ขึ้น `flagged` (ยังออกข้อสอบได้จนกว่าผู้ปกครองสั่งพัก ตั้งได้ที่ `flagged_policy`) |
| `source` | ข้อความ | เช่น `original`, `adapted-from-style:triam-udom` ห้ามคัดลอกข้อสอบจริงลิขสิทธิ์ |

กติการะบบตอน import: id ซ้ำ → ข้ามและรายงาน; `answer`/`skill`/`subject` ผิดรูปแบบ → ข้ามแถว (เมนู **Pre-test › ตรวจคลังข้อสอบ** แสดงผลตรวจ)

### 3.2 แท็บ `Sessions` (1 แถว = 1 การสอบ หรือ 1 ลิงก์ที่ออกให้)

| คอลัมน์ | ความหมาย |
|---|---|
| `session_id` | UUID (ใช้เป็นกุญแจเข้าถึง session) |
| `token` | โทเคนในลิงก์ใช้ครั้งเดียว (สุ่ม 24 ตัวอักษร) |
| `status` | `issued` (ออกลิงก์ยังไม่เริ่ม) → `in_progress` → `submitted` / `expired_auto` / `void` |
| `mode` | `mock_subject` / `mock_full` / `drill_auto` / `drill_custom` |
| `subjects` | JSON เช่น `["english","thai_social","art"]` |
| `config_json` | JSON พารามิเตอร์ (วิชา ทักษะที่เลือก จำนวนข้อ เวลา) ที่ผู้ปกครองกำหนดตอนสร้างลิงก์ — ถ้าเป็นลิงก์ที่ลูกเลือกเองได้ ให้เว้นว่าง |
| `issued_at` | เวลาออกลิงก์ |
| `started_at` / `started_ms` | เวลากด "เริ่มสอบ" (server) |
| `plan_json` | แผนเวลา: `[{subject, duration_ms, start_ms, deadline_ms, closed_reason}]` |
| `current_idx` | ดัชนีวิชาปัจจุบันใน plan |
| `submitted_at` | เวลาปิด session |
| `submit_reason` | `manual` / `time_up` / `sweep` |
| `tab_switches` | จำนวนครั้งที่สลับแท็บ/ออกจากหน้าต่าง |
| `reveal_policy` | `immediate` / `parent_release` (คัดลอกค่าจาก Settings ตอนเริ่ม) |
| `review_released` | `TRUE` เมื่อผู้ปกครองเปิดเฉลยให้ลูก |
| `score_pct` / `n_correct` / `n_wrong` / `n_skipped` / `n_total` | สรุปคะแนนรวม (เขียนตอนปิด) |
| `used_sec` | เวลาที่ใช้จริงรวม |
| `label` | ป้ายที่ผู้ปกครองตั้งได้ เช่น "รอบที่ 2" (ว่างได้) |

**ลิงก์ใช้ครั้งเดียว:** token ถูก "ใช้" ตอนกดเริ่มสอบ (status `issued`→`in_progress`) หลังจากนั้นลูกกลับเข้ามาต่อ session เดิมได้ด้วยลิงก์เดิม (ผูกกับ `session_id` ภายใน URL fragment/คุกกี้) แต่เปิด session ใหม่ด้วย token เดิมไม่ได้

### 3.3 แท็บ `Answers` (1 แถว = 1 ข้อใน 1 session; สร้างล่วงหน้าตอนเริ่มสอบ)

| คอลัมน์ | ความหมาย |
|---|---|
| `answer_key` | `session_id|question_id` |
| `session_id`, `question_id` | |
| `subject`, `skill`, `difficulty` | คัดลอกจาก Questions ณ ตอนสอบ (ผลย้อนหลังไม่เพี้ยนถ้าแก้ข้อสอบภายหลัง) |
| `position` | ลำดับข้อใน session (1..n) ภายในวิชา |
| `subject_idx` | วิชาที่เท่าไรใน plan |
| `option_order` | JSON เช่น `["C","A","D","B"]` = ลำดับตัวเลือกที่แสดง (ตัวอักษรเดิมใน Questions) |
| `chosen` | ตัวเลือกที่ตอบ (ตัวอักษรเดิม) หรือว่าง |
| `is_correct` | TRUE/FALSE/ว่าง (ว่าง = ข้าม/ไม่ได้ตอบ) — คำนวณฝั่ง server ตอนปิดวิชา (Drill: ตอนตอบ) |
| `flagged` | ปักธง |
| `skipped` | กดข้าม |
| `time_spent_ms` | เวลาสะสมที่เปิดข้อนี้ (clamp ตามที่ server เห็นจริง) |
| `visits` | จำนวนครั้งที่เปิดข้อนี้ |
| `answered_at` / `updated_at` | |
| `late_rejected` | จำนวนครั้งที่ server ปฏิเสธเพราะหมดเวลา (ไว้ตรวจสอบ) |

### 3.4 แท็บ `Results` (1 แถว = session × วิชา × ทักษะ; เขียนตอนปิดวิชา/session)

`result_id`, `session_id`, `mode`, `subject`, `skill`, `finished_at`, `n_total`, `n_correct`, `n_wrong`, `n_skipped`, `pct`, `avg_time_sec`, `d1_n`, `d1_correct`, `d2_n`, `d2_correct`, `d3_n`, `d3_correct`

ใช้เป็นแหล่งข้อมูลของ Dashboard (เร็ว ไม่ต้องสแกน Answers ทั้งหมดทุกครั้ง) ส่วนรายข้อ/ข้อที่ผิดซ้ำอ่านจาก Answers

## 6. กลไกจับเวลาฝั่ง server

**หลักการ:** เวลาในอำนาจของ server (`Date.now()` ใน Apps Script) เท่านั้น client ส่งเวลามาไม่ถูกเชื่อถือ

### 6.1 การเริ่ม
- ลูกกด **"เริ่มสอบ"** → server (ภายใต้ `LockService`) ตรวจ token → สุ่มข้อ → สร้างแถว Answers ทั้งหมด → เขียน `started_ms` และ `plan_json`
  - Mock รายวิชา/Drill: plan มี 1 ช่วง `deadline = started + duration`
  - Mock เต็มชุด: ช่วงที่ 1 เริ่มทันที ช่วงถัดไปยังไม่มี `start_ms` จนกว่าจะถึงตัว
- หน้าจอก่อนกดเริ่มแสดงข้อมูลชัดเจน (วิชา เวลา "เมื่อกดเริ่มแล้วเวลาจะเดินต่อแม้ปิดหน้าจอ")

### 6.2 การเปลี่ยนวิชา (Mock เต็มชุด)
- ลูกกด "จบวิชานี้ ไปวิชาต่อไป" (มีกล่องยืนยัน) → ปิดวิชาปัจจุบันที่เวลา `now`, วิชาถัดไปเริ่มที่ `now` และ `deadline = now + duration`
- **หมดเวลาวิชา:** ถือว่าวิชาปิดที่ `deadline` เดิม วิชาถัดไปเริ่มที่ **`deadline` ของวิชาก่อนหน้า** (ไม่ใช่ตอนลูกเปิดหน้ามา) ดังนั้นปิดแท็บไปไม่ได้เวลาเพิ่ม ถ้าผ่านไปหลายวิชา ระบบไล่ปิดต่อเนื่อง (cascade) ให้ครบ
- วิชาที่ปิดแล้ว **ย้อนกลับไม่ได้** server ปฏิเสธการบันทึกข้อของวิชาที่ปิดแล้ว (`closed`) และ client ไม่แสดงปุ่มย้อน
- วิชาสุดท้ายหมดเวลา/กดส่ง → `status = submitted`, `submit_reason = time_up|manual` แล้วล็อก session

### 6.3 ฟังก์ชันกลาง `evaluate(session, now)` (รันทุกครั้งที่มีคำสั่งใดๆ เข้ามา)
```
loop:
  cur = plan[current_idx]
  if now > cur.deadline_ms:           # ไม่รวม grace ตอนตัดวิชา
     close(cur, reason='time_up', at=cur.deadline_ms)
     if มีวิชาถัดไป: next.start_ms = cur.deadline_ms; next.deadline_ms = start + duration; current_idx++ ; continue
     else: finalize(session, 'time_up'); break
  else break
```
ผลคือสถานะถูกต้องเสมอแบบ "lazy" โดยไม่ต้องมี trigger แต่ระบบมีตัวสำรอง (§6.5)

### 6.4 การรับคำตอบ `saveAnswer`
รับ `(session_id, question_id, chosen, flagged, skipped, delta_ms)`; ภายใต้ lock:
1. `evaluate()` ก่อนเสมอ
2. ปฏิเสธถ้า session ไม่ใช่ `in_progress` หรือข้อนั้นไม่อยู่ในวิชาปัจจุบัน (`reason: closed`)
3. ปฏิเสธถ้า `now > deadline_ms + grace_sec` (`reason: late`) และเพิ่ม `late_rejected`
   - คำตอบที่มาถึงในช่วง `deadline < now ≤ deadline+grace` **รับได้** (เผื่อ autosave ที่ออกก่อนหมดเวลาแต่เครือข่ายช้า) แต่ client ต้องส่งคำตอบก่อนเวลาเท่านั้น
4. `delta_ms` ถูก clamp ไม่ให้เกิน (now − เวลา event ล่าสุดของ session ที่ server เห็น)
5. เขียนแถว Answers (อัปเดตในที่เดิม) และคืน `remaining_ms` ปัจจุบัน
6. ตอบกลับทุกครั้งด้วย `{server_now, deadline_ms, remaining_ms, current_idx, status}` เพื่อให้ client ซิงก์นาฬิกา

### 6.5 การปิดอัตโนมัติเมื่อไม่มีใครเปิดหน้า
- Time-driven trigger ทุก 5 นาที (`sweepExpiredSessions`) ปิด session ที่หมดเวลาแล้วและคำนวณผล (ติดตั้งผ่านเมนู **Pre-test › ติดตั้งตัวตั้งเวลา** ขั้นตอนอยู่ใน README)
- Dashboard ก็เรียก sweep ทุกครั้งที่เปิด

### 6.6 ฝั่ง client
- รับ `remaining_ms` + `server_now` แล้วนับถอยหลังด้วย `performance.now()` (ไม่พึ่งนาฬิกาเครื่อง) ซิงก์ใหม่ทุก autosave และทุก 30 วินาที
- แถบนาฬิกาตรึงบนหน้าจอ เตือนตอนเหลือ **5 นาทีและ 1 นาที** (แถบเปลี่ยนสี + ข้อความ ไม่เป็น popup ที่บังโจทย์)
- ถึง 0 → ขึ้นหน้า "หมดเวลาวิชานี้" แล้วถาม server เพื่อเข้าวิชาต่อไปหรือหน้าผลลัพธ์ (ใช้สถานะจาก server ไม่ตัดสินเอง)
- รีเฟรช/เปิดใหม่ → เรียก `getState` ได้ตำแหน่งข้อ คำตอบเดิม ธง และเวลาที่เหลือจริง
- นับสลับแท็บด้วย `visibilitychange` + `blur` ส่ง `logTabSwitch` (ไม่ได้ห้าม แค่บันทึก แสดงใน Dashboard)
- ถ้า autosave ล้มเหลวจากเครือข่าย: เก็บคิวในหน่วยความจำ แสดงสถานะ "ยังไม่ได้บันทึก" และลองใหม่อัตโนมัติ; ถ้า server ตอบ `late/closed` แสดงข้อความว่าคำตอบนั้นไม่ถูกบันทึก

### 6.7 Drill
ใช้ plan 1 ช่วงเหมือนกัน แต่หลังตอบแต่ละข้อ client เรียก `checkAnswer` ได้เฉลย + คำอธิบายทันที แล้ว**ล็อกข้อนั้น** (เปลี่ยนคำตอบไม่ได้หลังเห็นเฉลย) และถือว่าเป็นคะแนนข้อนั้น

## 7. Flow หน้าสอบ (ลูก)

### 7.1 เข้าและเลือกโหมด

### 7.2 หน้าทำข้อสอบ
- บน: ชื่อวิชา · นาฬิกานับถอยหลัง · สถานะบันทึก ("บันทึกแล้ว ✓")

- แผงเลขข้อ (ด้านข้าง/แถบพับได้บนมือถือ): สีบอกสถานะ ตอบแล้ว / ข้าม / ยังไม่ทำ / ปักธง / ข้อปัจจุบัน กดเพื่อกระโดดได้ (ภายในวิชาปัจจุบันเท่านั้น)

- ปุ่ม "ส่งวิชานี้ / ส่งข้อสอบ" มีหน้าสรุป (ตอบแล้ว n / ข้าม n / ปักธง n) และยืนยันก่อนส่ง

### 7.3 หลังสอบ
- **หน้าสรุป:** คะแนนรวม % · ถูก / ผิด / ข้าม · เวลาที่ใช้ (Mock เต็มชุดแสดงรายวิชา + รวม)
- **หน้าทบทวน (ตามนโยบายเฉลย §7.4):** ไล่ทีละข้อ แสดงคำตอบของลูก เฉลย ทำไมข้อนี้ถูก ทำไมตัวเลือกอื่นผิด หลักที่ควรจำ รูปประกอบ ตัวกรอง "เฉพาะข้อที่ผิด" / "เฉพาะข้อที่ปักธง" / "ข้อที่ข้าม"
- ปุ่ม **"แจ้งเฉลยผิด"** ต่อข้อ (ช่องพิมพ์เหตุผล) → เขียนแท็บ Reports และตั้ง `Questions.status = flagged` ตาม `flagged_policy`

### 7.4 นโยบายแสดงเฉลย (Mock)

- Drill แสดงเฉลยทันทีเสมอ

## 8. Dashboard (ผู้ปกครอง) `?page=dashboard`

### 8.1 สิทธิ์
เปิดได้เฉพาะอีเมลเท่ากับ `owner_email` (เช็คฝั่ง server ทุก API ไม่ใช่แค่หน้าแรก) ไม่ตรง → หน้า "ไม่มีสิทธิ์" ไม่ส่งข้อมูลใดๆ

### 8.2 แท็บและเนื้อหา
- **ภาพรวม:** ผลล่าสุดของแต่ละวิชา (% + 🟢🟡🔴 + "สอบล่าสุดเมื่อ …") · คะแนนรวมภาพรวม = เฉลี่ยถ่วงน้ำหนักตามจำนวนข้อของผลล่าสุดแต่ละวิชา · radar chart ทักษะทั้งหมด · กราฟพัฒนาการแต่ละรอบ · ส่วน "ลิงก์สอบ" · ส่วน "ข้อที่ลูกแจ้งว่าเฉลยผิด" · รายการ session ล่าสุดพร้อมป้าย
- **อังกฤษ / ไทยและสังคม / ความถนัดศิลป์ (แท็บละวิชา):**
  - % รายทักษะตามสี พร้อม "(จาก n ข้อ)"
  - radar ของวิชา
  - ผลแยกตามระดับความยาก (ง่าย/กลาง/ยาก)
  - เวลาที่ใช้ต่อข้อ (เฉลี่ยรายทักษะ และเทียบกับเวลาเฉลี่ยที่ blueprint คาดไว้)
  - กราฟพัฒนาการต่อรอบของวิชานั้น
  - รายการข้อที่ผิดซ้ำ (ผิด ≥ 2 ครั้ง) พร้อมทักษะ
  - รายการ session ของวิชานั้น
- **ป้ายประเภทรอบ:** `สอบรายวิชา` / `สอบเต็มชุด` / `Drill อัตโนมัติ` / `Drill เลือกเอง` (สีต่างกัน) ในทุกรายการและจุดบนกราฟ
- **ดูย้อนหลังทีละข้อ:** กด session → รายการข้อทั้งหมด (คำตอบลูก เฉลย เวลาที่ใช้ ธง จำนวนสลับแท็บ) พร้อมคำอธิบายครบ
- **ลิงก์สอบ:** สร้างลิงก์ (เลือกโหมด/วิชา/ป้ายกำกับ) → แสดง URL ให้คัดลอก · รายการลิงก์ที่ออกแล้ว พร้อมสถานะ ยังไม่ใช้ / ใช้แล้ว · ยกเลิกลิงก์ที่ยังไม่ใช้ได้
- **ตั้งค่าเฉลย:** สวิตช์นโยบายเริ่มต้น + ปุ่ม "เปิดเฉลยให้ลูก" รายครั้ง
- **จัดการ Reports:** รายการแจ้งผิด (ข้อ เหตุผล วันที่) ปุ่ม "พักข้อนี้" / "ข้อถูกแล้ว ปิดเรื่อง" — หรือแก้ใน Sheet โดยตรงก็ได้

### 8.3 เรื่องการยืนยันอีเมล (ความเสี่ยงที่ต้องทดสอบจริง)
`Session.getActiveUser().getEmail()` ในบัญชี Gmail ทั่วไปคืนค่าได้เมื่อ Web App ตั้ง **"Execute as: Me"** และ **"Who has access: Anyone with Google account"** (ผู้ใช้ต้องล็อกอิน) ถ้าตั้ง "Anyone" (ไม่ล็อกอิน) จะคืนค่าว่าง ผมจะทดสอบกับบัญชีของคุณตอน dev ถ้าไม่ได้ผล ทางเลือกคือ (ก) ลูกสอบได้โดยไม่ต้องล็อกอิน (Anyone) และ Dashboard ใช้ `parent_pin` แทน (ข) ใช้การตั้งค่า "Execute as user accessing" ซึ่งยุ่งกว่า — ผมแนะนำ (ก) ถ้าลูกไม่มีบัญชี Google

### 8.4 วิธีคำนวณ % รายทักษะ (ตรวจสอบได้ ใช้ในการทดสอบ)
สำหรับทักษะ *s* ใช้ session ของโหมด Mock (และ Drill ถ้า `skill_include_drill`) ที่มีข้อของ *s* เรียงใหม่→เก่า เอาไม่เกิน `recency_max_sessions` รอบ ให้ rank ของรอบล่าสุด = 0:
```
w_k       = recency_decay ^ rank_k
pct_s     = 100 × Σ(w_k × correct_k) / Σ(w_k × total_k)      # ข้อที่ข้ามนับเป็นผิด (อยู่ใน total)
n_s       = Σ total_k                                         # แสดงเป็น "(จาก n ข้อ)"
สี        = 🟢 ถ้า pct ≥ color_green_min, 🟡 ถ้า ≥ color_yellow_min, ไม่งั้น 🔴
```
คะแนนวิชา = ค่าเดียวกันคิดรวมทุกทักษะของวิชาโดยถ่วงด้วยจำนวนข้อ; ภาพรวม = ผลล่าสุดของแต่ละวิชา (ไม่ถ่วงข้ามเวลา) ถ่วงด้วยจำนวนข้อ

### 8.5 Drill อัตโนมัติ: การจัดสรรข้อ
ทักษะที่ 🔴🟡 ของวิชาที่เลือก: น้ำหนัก `wt = 100 − pct_s` (ยิ่งอ่อนยิ่งมาก) จัดสรรจำนวนข้อทั้งหมด `N` ตามสัดส่วน `wt` โดยขั้นต่ำ `drill_min_per_skill` ต่อทักษะ ปัดเศษให้รวมเท่ากับ N ถ้าไม่มีทักษะ 🔴🟡 เลย (ทุกทักษะ 🟢) ให้ฝึกทักษะที่ต่ำสุด 2 อันดับ

## 10. แผนทดสอบ (ส่งมอบพร้อมโค้ด)

โค้ดแยกฟังก์ชันตรรกะล้วน (ไม่แตะ Sheet) ออกมา เช่น `evaluatePlan`, `computeSkillStats`, `allocateDrill` เพื่อรันทดสอบด้วย Node ได้ (`apps-script/tests/`) ครอบคลุม:
1. หมดเวลาวิชาที่ 1 ระหว่างที่ไม่มีใครเปิดหน้า → เปิดมาอยู่วิชา 2 เวลาที่เหลือถูกต้อง (เริ่มนับจาก deadline เดิม)
2. cascade หมดหลายวิชาพร้อมกัน → ปิด session
3. saveAnswer ก่อนหมดเวลา รับ / ภายใน grace รับ / เกิน grace ปฏิเสธ / วิชาที่ปิดแล้วปฏิเสธ
4. รีเฟรชแล้วเวลาที่เหลือตรงกับ server
5. คำนวณ % รายทักษะแบบถ่วงน้ำหนักล่าสุด + "(จาก n ข้อ)" + เกณฑ์สี รวมกรณีขอบ (80.0, 60.0, ไม่มีข้อมูล)
6. ภาพรวมจากผลล่าสุดต่อวิชา; Drill ไม่ปนใน Mock
7. สุ่มข้อตาม blueprint, ไม่ซ้ำข้อที่เพิ่งทำ, กลุ่ม passage ไม่แตก
8. Drill อัตโนมัติ: จัดสรรข้อเรียงตามความอ่อน และปิดปุ่มเมื่อไม่มีผล Mock
9. ทดสอบจริงบน Apps Script ด้วยข้อสอบชุดเล็ก (ขั้นตอนที่ 3) เช็คการเขียน Sheet และ token ใช้ครั้งเดียว

## 10.1 ส่วนที่เปลี่ยนจาก spec ระหว่าง dev (โค้ดคือแหล่งอ้างอิงจริง: `apps-script/Setup.gs` › SCHEMA)
- เวลา `*_at` เก็บเป็นค่าวันที่ของ Sheets (อ่านง่ายในชีต) และ `*_ms` เก็บเป็นตัวเลขสำหรับคำนวณ
- Sessions เพิ่ม `submitted_ms`, `last_event_ms` (ใช้จำกัดเวลาต่อข้อ), `ans_row_start`/`ans_count` (ตำแหน่งแถว Answers ของรอบนั้น จะได้ไม่ต้องอ่านทั้งแท็บทุกครั้งที่ autosave)
- Answers เพิ่ม `correct` (เฉลย ณ ตอนสอบ) เพื่อตรวจคะแนนโดยไม่ต้องอ่านคลังข้อสอบ แท็บ Answers ลูกมองไม่เห็นอยู่แล้ว (ลูกเข้าผ่านเว็บเท่านั้น)
- คะแนนวิชาในแท็บวิชาของ Dashboard ใช้สูตรถ่วงรอบล่าสุดแบบเดียวกับทักษะ (§8.4) แต่คิดรวมทุกข้อของวิชา ส่วน "ภาพรวม" ยังเป็นผลล่าสุดต่อวิชาตามเดิม
- การสุ่ม: ถ้าต้องเลือกระหว่าง "เลี่ยงข้อที่เพิ่งทำ" กับ "สัดส่วนความยาก" ระบบเลือกเลี่ยงข้อที่เพิ่งทำก่อน
- เพิ่ม `api_ping` ให้หน้าสอบซิงก์นาฬิกากับ server ทุก 30 วินาที และทุกครั้งที่กลับมาที่แท็บ
- ใน Mock เต็มชุด ปุ่มส่งในวิชาที่ยังไม่ใช่วิชาสุดท้ายคือ "จบวิชานี้ → วิชาต่อไป" (ส่งทั้งชุดก่อนถึงวิชาสุดท้ายไม่ได้)
